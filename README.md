# Лабораторная №2 — Контакты устройства

Flutter/Dart, Android, русский интерфейс. Проект продолжает черновик из `lab2_contacts_handoff.zip`. Логика и экраны сохранены в одном `lib/main.dart`, чтобы их было удобно разбирать на защите.

Ветка `lab-2` создана от `origin/main` репозитория `anotherash/mobdev`. Лабораторная №1 остаётся в своей ветке. В исходной инструкции указана `master`, но в этом репозитории базовая ветка называется `main`. Оригинал инструкции сохранён в `docs/REPOSITORY_RULES.md`; пути Java в ней заменяются обычной структурой Flutter.

## Запуск на этом Mac

Открыть в VS Code папку `/Users/kirkramar/Documents/MobileDevLab2/mobdev` целиком. Android Studio → Device Manager → запустить эмулятор. В терминале:

```sh
cd /Users/kirkramar/Documents/MobileDevLab2/mobdev
export PATH="/Users/kirkramar/Documents/flutter/bin:$PATH"
flutter pub get
flutter gen-l10n
flutter run
```

Если устройств несколько: `flutter devices`, затем `flutter run -d emulator-5554`.

```sh
flutter analyze
flutter test
flutter build apk --debug
```

Учебный APK: `build/app/outputs/flutter-apk/app-debug.apk`. Сборка для демонстрации, не публикация в магазине. Проверено с установленными Flutter 3.47.6 / Dart 3.13.5 и Android-эмулятором API 37. Новую установку SDK выполнять не нужно.

## Соответствие заданию

| Требование | Реализация |
|---|---|
| Разрешение на чтение | `READ_CONTACTS`, запрос при первом открытии и повторный запрос кнопкой |
| Отказ и пустая книга | Разные состояния и сообщения |
| Список | Имя, основной номер (или первый), индикатор email |
| Карточка | Все телефоны/email; имя, фамилия, организация, должность, адреса, заметки, сайты и даты при наличии |
| Поиск и сортировка | По имени, без повторного чтения адресной книги; А–Я / Я–А, счётчик |
| Загрузка/ошибки | Отдельные состояния, повторная попытка чтения |
| Окончательный отказ | Кнопка открытия настроек вместо недоступного запроса |
| Возврат из настроек | Проверка доступа; чтение, если ещё нет кэша или доступ был отозван и выдан снова |
| Возврат из карточки/перестроение | Кэш сохраняется, повторного чтения нет |
| Отсутствующие данные | Подписи «Не указано», «Нет номера телефона», «Без имени» |
| Большие списки | `ListView.builder` создаёт строки по мере необходимости |
| Поворот и безопасные области | `SafeArea`, прокрутка, сохранение запроса/сортировки; Flutter restoration для этих двух настроек |
| Идентификатор | `ru.student.device_contacts` |
| Ресурсы строк | `lib/l10n/app_ru.arb`, `app_en.arb`; Android-название в `strings.xml` |

При изменении контактов в другом приложении нажать «Обновить». Приложение намеренно не перечитывает книгу при каждом возвращении на экран. Оно только читает контакты и не звонит, не отправляет сообщения, не редактирует адресную книгу.

## Где что находится

- `lib/main.dart`: весь учебный код. `ContactEntry` — данные контакта; `ContactsRepository` — доступ к Android через плагин; `ContactsController` — разрешения, кэш, состояния, фильтрация и сортировка; `ContactsApp` — тема/локализация; `ContactsScreen` — список; `ContactDetailsScreen` — карточка; вспомогательные виджеты — сообщения и поля.
- `lib/l10n/*.arb`: тексты интерфейса. `app_localizations*.dart` генерируются командой `flutter gen-l10n`, вручную их менять не нужно.
- `pubspec.yaml` и `pubspec.lock`: зависимости и зафиксированные версии. Вместо старых `contacts_service`/`permission_handler` используется `flutter_contacts 2.5.0`.
- `android/`: Android-оболочка, Gradle, разрешение, идентификатор и Kotlin `MainActivity`. Экран контактов написан на Dart, Kotlin только запускает Flutter.
- `test/`: 23 проверки контроллера, преобразования данных и интерфейса.
- `tools/seed_emulator.py`: вымышленные контакты для пустого эмулятора.
- `docs/COMMIT_AND_PUSH.md`: самостоятельный коммит и отправка.
- `docs/HANDOFF_REVIEW.md`: исправления черновика и результаты проверок.

Поток данных: экран вызывает контроллер → контроллер проверяет разрешение через репозиторий → репозиторий получает Android-контакты → контроллер сохраняет их в памяти и уведомляет экран через `ChangeNotifier`. Поиск/сортировка работают только с этим списком. Кэш очищается при отказе. Пока выполняется чтение, второй такой запрос не запускается. После чтения доступ проверяется ещё раз, чтобы не показать данные, если разрешение успели отозвать.

## Сценарий защиты

1. Первый запуск: отказать. Показать «Нет доступа к контактам».
2. «Запросить доступ» → разрешить. При двух отказах открыть настройки приложения и выдать доступ там.
3. Показать список и Анну Тестову: основной номер заканчивается на 0102, в карточке два телефона, два email и дополнительные поля.
4. Борис — без телефона, Вера — без email, Глеб — только имя. Все карточки открываются.
5. Ввести часть имени, показать счётчик, обе сортировки и отсутствие результатов для несуществующего имени.
6. Оставить поиск и Я–А, повернуть экран: запрос и сортировка сохраняются.
7. Вернуться из настроек без изменения разрешения: список остаётся в кэше.
8. Отозвать разрешение: контакты скрыты. Android может завершить процесс приложения при отзыве — тогда открыть приложение снова. Выдать разрешение и вернуться: список загрузится.
9. Пустая книга проверяется на эмуляторе без контактов; ошибка чтения и число обращений к источнику проверяются автоматическими тестами.

Шесть вымышленных контактов уже добавлены в `emulator-5554`. Для другого **пустого** эмулятора с тем же идентификатором:

```sh
python3 tools/seed_emulator.py
```

Скрипт отказывается работать с реальным устройством и непустой адресной книгой. Для демонстрации первого запроса можно очистить данные именно приложения с идентификатором `ru.student.device_contacts`. Системное хранилище контактов очищать не нужно.
